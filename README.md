# Spatiotemporal Hotspot Mapping and Crime Prediction in Mexico City

This project studies how recorded crime changes across Mexico City and uses historical crime patterns to predict the number of incidents expected in each police cuadrante during the next month.

The goal is to test whether adding information about neighboring cuadrantes improves predictions compared with using an area's own crime history. The current implementation combines PostgreSQL/PostGIS for spatial data and feature engineering with Random Forest and XGBoost for prediction.

## Data

Crime counts and cuadrante boundaries come from [HoyoDeCrimen](https://api.hoyodecrimen.com/). The verified dataset contains:

- 847 police cuadrante polygons.
- Monthly counts for 20 recorded-crime categories, from January 2019 through August 2026.
- 1,558,480 source records and 77,924 cuadrante-month observations.

The prediction target is the sum of the 20 loaded categories for a cuadrante in the next month. It does not represent all crime in the city or an individual's risk.

## Current implementation

1. Store cuadrante boundaries and monthly crime records in PostgreSQL/PostGIS.
2. Validate source coverage, duplicate keys, counts, and polygon geometry.
3. Build a monthly feature table containing current counts, one-month and three-month lags, three-month and six-month rolling averages, and calendar features.
4. Use PostGIS `ST_Touches` to identify neighboring cuadrantes and calculate neighboring crime sums, means, and lagged means.
5. Train Random Forest and XGBoost with temporal features alone and with spatial features added.
6. Compare the models with persistence and rolling-average baselines using chronological validation and test periods.

A feature row for month t uses information through t to predict t+1. Missing calendar months remain unknown rather than being filled with zero. The latest row without a known next-month outcome is excluded from training.

## Initial results

Training uses target months from July 2019 through August 2025. Validation covers September 2025 through February 2026. The test period is March–August 2026, with 5,082 observations across all 847 cuadrantes. Models are refitted on training plus validation before test evaluation.

| Model | Test MAE | Test RMSE | Test R² |
|---|---:|---:|---:|
| Persistence: repeat the current month's count | 1.4111 | 2.0226 | -0.2052 |
| Three-month average | 1.2210 | 1.6737 | 0.1748 |
| Random Forest: temporal features | 1.1665 | 1.5663 | 0.2773 |
| Random Forest: temporal + spatial features | 1.1487 | 1.5488 | 0.2933 |
| XGBoost: temporal features | 1.1458 | 1.5391 | 0.3022 |
| XGBoost: temporal + spatial features | **1.1401** | **1.5347** | **0.3061** |

Lower MAE and RMSE indicate better predictions. MAE is the average absolute error in recorded incidents per cuadrante-month.

XGBoost with spatial features had the lowest validation MAE and test MAE. Its test MAE was 19.2% lower than persistence. Adding neighboring-crime features reduced MAE by approximately 1.5% for Random Forest and 0.5% for XGBoost compared with their temporal-only versions. These are modest gains from one chronological holdout.

See [the results summary](ml-baselines/RESULTS.md) and [detailed metrics](ml-baselines/results/metrics.json).

## Getting started

The data-loading scripts require PostgreSQL with PostGIS and a Python environment with the root `requirements.txt` installed. Create the database and enable PostGIS:

```sql
CREATE DATABASE cdmx_crime;
```

Connect to `cdmx_crime`, then run:

```sql
CREATE EXTENSION IF NOT EXISTS postgis;
```

Copy `.env.example` to `.env` and set your own database connection details. Keep `.env` out of version control.

The original data-loading steps are:

```bash
python scripts/test_hoyodecrimen.py
python scripts/load_cuadrantes.py
python scripts/check_postgis.py
python scripts/load_crime_series.py
```

For the current feature pipeline and Random Forest/XGBoost experiments, follow the [ML reproduction instructions](ml-baselines/README.md). The feature build uses PostgreSQL connection settings such as `PGDATABASE`, `PGHOST`, and `PGUSER`; it does not read the root `.env` automatically. The ML experiments have their own dependency files so they can run separately from optional deep-learning dependencies.

## Limitations and future work

These results evaluate a sequence of one-month-ahead predictions for the same cuadrantes. Each forecast assumes the origin month's counts are available. The evaluation does not reconstruct reporting delays or historical data revisions, and August 2026 reporting finality has not been independently established.

The data reflects recorded crime and may be affected by reporting and enforcement patterns. Predictions should not be interpreted as individual risk or used alone to make policing decisions.

Possible extensions include verified policy/law variables, additional chronological evaluation periods, hotspot classification, deep spatiotemporal models, and an interactive map. Those features are not part of the current implementation.
